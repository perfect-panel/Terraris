# B4 控制面与运行时

状态：B4 library 与模拟验证已完成；B5 已增加 [VLESS 实际驱动、共享监听器与 run CLI](vless.md)。本文保留 B4 的接口与事务契约，具体协议能力以 B5 文档为准。

## 组件与装配

| 入口 | 职责 |
| --- | --- |
| `scheduler::Scheduler` | 有界维护任务、每任务不重叠、独立退避、超时与 panic 结果、关键任务并发余量 |
| `users::Store` / `Reconciler` | 有界用户快照、凭据索引、本地 revision、认证版本、事务提交及会话撤销 |
| `runtime::RuntimeFactory` | 校验并构建代次共享服务、私有协议驱动与监听器；当前由 VLESS 驱动提供 |
| `protocol::runtimekit::Core` | 共享用户与报告状态、进程 buffer 预算、任务所有权、准入许可和会话排空 |
| `Controller` | 单协议用户、alive、流量、在线与有效期任务；提交前检查当前代次所有权 |
| `Supervisor` | 配置拉取、候选准备、原子发布、旧代次退役、最终报告与关闭 |
| `reports::Reports` | 按协议作用域保留的有界内存增量与在线记录；报告 ACK 只确认对应批次 |

调用方为 `Supervisor::new` 提供一个面板 `Connection`、真实 `RuntimeFactory`、进程级 `BufferScope`、上限、`Metrics`、`FingerprintSink`，以及可选 `StatusSampler`。PPanel 的 `CertificateFingerprints` 已实现 sink，必须传入创建该 Connection 时使用的同一实例。没有 sampler 时不发送虚构的 CPU、内存、磁盘数据。

`sync_config` 完成一次同步，并在成功发布后启动该代次的维护任务。`run` 额外驱动配置轮询、退役清理和已移除协议的报告重试；其 context 取消后进入显式关闭。单独调用 `sync_config` 的宿主也必须调用 `close`，并定期调用 `reap_retired`。Drop 或强制 abort 只能停止准入和请求取消，确认任务、socket 和 buffer 回收仍需要等待 `close`。

默认上限为 16 个配置协议、32 个进程内保留的协议作用域、2 个等待清理的退役代次、每运行时 4096 个任务、每作用域 100000 个用户和会话，以及各 100000 个流量用户和在线 IP 记录。作用域暂不自动删除，达到上限会拒绝新增作用域；原有待确认报告不会被淘汰。元数据使用数量上限，不计入 buffer 字节额度，也不代表 RSS 上限。

## 事务与代次切换

1. 拉取并保留候选配置验证器。相同规范化配置或有效的 `304` 只更新验证器。
2. 创建一份代次共享服务；所有协议使用同一进程 buffer 预算、稳定的协议 Store 与 Reports。
3. 在关闭的 AdmissionGate 后准备各协议私有认证快照，再准备全部监听器。候选取消与活跃运行时使用不同取消域。
4. 持有统一发布许可，检查所有用户源 revision，逐个提交私有认证和监听器。任一步失败都关闭候选，不修改活跃 Store、配置验证器和证书指纹。
5. 所有可失败操作成功后，发布共享用户状态、配置、指纹和代次，关闭旧准入门、打开新准入门。此处之后不以迟到的取消将成功解释为失败。
6. 在锁外唤醒撤销等待者、停止旧监听器。新维护任务等待旧维护 future 全部退出，旧 Controller 无法提交迟到响应。
7. `reap_retired` 等待旧会话至首次退役时确定的截止时间，再取消、abort、join 和关闭共享服务。重试不会重新延长排空期限。

认证提交与监听器提交必须是有界本地操作，不能执行网络/磁盘 I/O、panic 或重新进入 Core/发布锁。认证提交失败必须保留旧认证表；监听器失败不得破坏活跃代次。整个候选仍可丢弃，实际驱动必须释放部分准备资源。

每个连接、UDP 关联和多路复用子流都必须在协议认证后调用 `Core::admit`，并在等待设备、DNS、拨号和转发时使用许可的 `OperationContext`。只绑定 socket 不表示准入已开放。认证成功必须由真实协议库证明，Core 不替代密码协议。

未知协议可以跳过；明确要求但不可用的协议使候选失败。空协议列表或全部协议禁用会关闭入站并保持配置同步。当前保守拒绝受支持协议的重复端口；同端口重载是否可行由驱动实现，B5 VLESS 已提供同地址共享 ingress；没有依靠 reuseport 实现切换。DNS、路由、出站、协议安全与传输配置的完整校验属于 factory 的强制契约，不能静默忽略。

## 用户与会话

用户更新先构造完整候选，再准备认证表；提交时同时比较源 Store 和本地 revision。新增、删除、凭据变更和限制变更有独立 Diff。删除及改密钥使原认证版本失效；相同 ID/密钥重新加入也不能恢复旧许可。

旧会话在排空期间读取同一个稳定 Store，能够看到新代次的限制与撤销。限制字段由稳定 Store 提供；B5 flow 已实现共享限速、设备租约和实际转发路径。

`304` 延长已存在快照的有效期，成功空列表撤销全部用户。暂时请求失败保留快照；401/403 或有效期到期会暂停用户并清除验证器，恢复需要完整快照。默认最长未确认时间为 15 分钟。准入直接检查单调时间，不依赖维护任务及时运行；有效期任务同时通知已有会话退出。

撤销在发布许可内设置单调标记，在释放锁后通知等待者。`OperationContext::child` 继承撤销约束；子域不能移除它或用另一个用户的约束替换。协议任务必须持续使用该 context，才有实际的 I/O 中断效果。

## 调度与报告

Scheduler 用结构化 future 集合保存在途任务。每项完成后安排下一次运行，失败按独立指数退避，上限为配置值。普通任务最多使用 `concurrency - critical_reserve` 个名额；users、online、有效期任务属于关键通道。任务 future 的 panic 记为失败，不中止其他任务；宿主 panic hook 仍可能输出信息。所有 future 必须协作让出执行权，无法抢占阻塞代码。

Controller 的 users/alive 使用 pull 周期，traffic 使用 push 周期，online 周期不超过 60 秒，有效期检查不超过 1 秒。初次用户快照在准备阶段获取；发布后从一个周期后开始轮询。主机状态每代次采样一次，再发往该代次各协议状态端口；证书指纹只取已发布驱动。

流量报告保留不可变增量批次，发送期间新增的字节不被旧 ACK 清除。单项不超过面板的 10 TiB 限额，单批最多 1000 项；超大累计值分次报告，轮转游标避免小 ID 长期占用批次。失败或取消释放在途占用并保留未确认数据，整数溢出或记录数满返回错误，不饱和丢弃计费字节。调用方必须停止或另行保留未能登记的增量。

在线记录包含活跃地址及未确认的短会话，规范化 IPv4-mapped IPv6，并按面板 policy 和 10000 项上限分批。批次使用版本确认，旧 ACK 不会抹掉发送期间同一 IP 的新短会话。已结束且确认的地址不再续期。关闭时继续冲刷低于常规阈值的流量和未确认在线记录；移除协议仍保留可重试的报告。

Reports 当前只在内存中，既不防进程崩溃丢失，也不能解决面板已计费但 ACK 丢失后的重复收费。设备 `/device` 准入、TTL 校验与租约撤销已在 B5 接入，持久化报告队列仍待后续实现。

## 验证范围

本地测试覆盖候选部分提交失败、私有监听器失败、用户 revision 竞争、旧代次迟到响应、认证失败恢复、跨代次撤销/限制读取、未确认报告保留、取消回收、退役容量、固定排空期限、共享状态采样和持续 run 退出。

调度与报告测试使用可控时间验证并发余量、独立退避、超时、panic 隔离、取消释放、批次部分确认、流量溢出与上限、在线短会话版本竞争。VLESS 协议与 Xray 本地互通、限速和设备 TTL 已在 B5 补充验证；真实面板、证书装载/更新、跨节点设备竞争、性能和部署仍待验证。
